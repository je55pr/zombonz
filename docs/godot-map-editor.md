# Godot map authoring

The map editor targets **Godot 4.7 .NET**, with its C# SDK pinned to **4.7.2**. The editor plugin, map nodes, Inspector and smoke check are written in C#. The game runs in the browser with Three.js and consumes the exported JSON.

Install the [.NET edition of Godot 4.7.2](https://godotengine.org/download/archive/4.7.2-stable/) and a 64-bit [.NET SDK](https://dotnet.microsoft.com/download) (8 or newer). The standard Godot download cannot run the C# plugin. The project targets `net8.0`; a newer SDK such as .NET 10 can build it. Node.js is also required for map validation and browser previews.

From the repository root, run:

```text
npm ci
npm run editor:setup
```

Then import/open `tools/godot-map-editor/project.godot` in the **.NET** editor. The **Zombonz Maps** dock appears on the right. If it is disabled, build the project with Godot's **Build** button, then enable **Zombonz Map Authoring** under **Project → Project Settings → Plugins**. Build again after changing C# scripts. An external C# editor can be chosen under **Editor → Editor Settings → Dotnet → Editor**.

`editor:setup` builds the C# project and migrates local scenes that still reference the old GDScript nodes. It preserves transforms and exported values, and saves an original `.tscn.gd-backup` beside each migrated scene. Close Godot before running setup on an existing authoring project. Local scenes and their backups are ignored by Git; keep any unsent level work in JSON by exporting it.

Set the dock's source to `../../src/maps/data/bunker.v1.json` or `../../src/maps/data/asylum.v1.json`, then click **Import map into scene** to generate an authoring scene from the committed JSON. Godot scenes under `maps/` are local editor artifacts; commit the JSON after exporting. The dock provides:

Imported scenes use the **same GLB prop models and environment textures as the browser game**, loaded from `public/assets`. Architecture previews include base color, normal, and packed occlusion/roughness/metallic maps, the map's chosen surface looks, gabled roofs, distinct floor/ceiling surfaces, prisms, and wall decals. Models use the browser's uniform fit, yaw, and foot anchoring, including the crowbar orientation correction. Gameplay previews include real explosive barrels, jeeps, trucks, painted perk machines, chalk wall guns, and procedural doors, debris, boarded barriers, mystery boxes, Pack-a-Punch machines, equipment shelves, power switches, and trap pylons. Spawn points have labeled human-sized capsule guides with footprints at floor height. Practical lights appear as coloured handles under **Lighting**; selecting one exposes its colour, intensity, range, decay, priority, flicker and power behavior. The map root exposes optional fog/exposure/ambient/moon atmosphere fields. The scene still uses neutral authoring lighting, so check the final mood with **Export and play in browser**; see [lighting and atmosphere](lighting.md).

Use the dock's **Labels**, **Spawn guides**, **Entry routes**, and **Collision boxes** switches to control editing guides. **Purchased wall guns** shows the mounted gun models for placement checks. It starts off: the game still begins with chalk outlines, and displays the physical gun after purchase. These switches are saved with the local scene and never change the map JSON or gameplay.

For an existing placeholder scene, click **Refresh models and textures** in the dock. This preserves object transforms and Inspector fields, so you can refresh before exporting unsaved level edits. Also refresh after changing an Asset, Hazard Kind, Perk ID, Weapon ID, door appearance, Width, or Max Boards, or resizing a prop, to update its preview. Move the object parent node rather than its generated **Art** children. Refresh replaces those preview children. Missing assets are reported in the dock and retain the previous editable view. Gameplay models use fixed runtime dimensions; resize barriers and doors through **Width**, and adjust their editable collision children as needed.

Door **Blocker** boxes and barrier **Inside**/**Route** points are children of their gameplay anchor, so moving or rotating the parent carries them together. Enable **Collision boxes** or **Entry routes** and select a child to adjust it separately. Barrier edits also update the matching window presentation, and changing a barrier ID updates its existing zombie spawn references on export. Rotate barriers in 90-degree steps to match the game's axis-aligned window frames. Wall guns, perk machines, and equipment buys export their facing from the parent's Y rotation. Mystery boxes carry their initial presentation/relocation position and fixed body when moved; additional relocation locations remain editable in JSON. Pack-a-Punch machines require rotations in 90-degree steps; other angles are rejected by the browser validator.

The first preview import generates binary resources in ignored `tools/godot-map-editor/preview-cache/`; later imports reuse the cache. Source content hashes invalidate changed assets automatically. Keep this local cache alongside your saved scenes, which reference it. Only the JSON needs committing. If recreating the editor on another machine, import the JSON to rebuild the cache and scenes.

If an older preview reports **Model has no meshes**, update the editor, run `npm run editor:setup` with Godot closed, reopen the project, and click **Refresh models and textures**. The fixed importer bypasses the old model cache automatically and converts Godot's intermediate import meshes into renderable meshes. It keeps GLB textures embedded in the ignored cache instead of extracting files beside the browser assets. Existing authoring transforms and fields are preserved; reimporting the map is unnecessary.

1. **Import map into scene** reads the JSON path in the dock (Bunker by default) and rebuilds its authoring scene. This is useful after editing JSON directly. Import replaces the saved scene, so export existing scene edits first.
2. Select a node in **Geometry**, **Props**, or **Gameplay** and use Godot's move and rotate tools (and scale for props or boxes). The Inspector exposes the fields relevant to that object. Use **Collision boxes** or **Entry routes** to edit linked blockers and approach points.
3. Choose an object type and click **Add selected object** to create a prop, greybox, collision box, zombie spawn, barrier, door, wall weapon, barrel, jeep, truck, navigation node, perk machine, Pack-a-Punch machine, equipment buy, or practical light. IDs are generated uniquely where applicable and can be edited. New barriers have immediately editable route/inside children and create a matching window presentation; new doors have an editable blocker and appearance. New navigation nodes start without neighbors, so connect them in JSON before expecting zombies to use them. New lights use the renderer's legacy warm defaults until their Inspector fields are changed.
4. **Validate open map** writes the current in-memory scene candidate to a temporary file and runs the same TypeScript validator used by the browser/CLI. The small C# validator is only an immediate structural preflight; it is not a second rulebook. **Export open map** applies only changed values to the JSON source, runs that same TypeScript validator before writing, and saves the scene. Import also refuses a source map that fails the shared validator. These actions require `node` on `PATH`. Invalid validation/export leaves the committed JSON unchanged and shows path-specific errors in the dock.
5. **Export and play in browser** runs the export, starts Vite on port 5173, and opens the selected map's start preview. Choose Solo from the game menu for normal round gameplay.

The Godot scene stores editor handles, and the versioned JSON is the browser's source of truth. A newly added object and its editable children receive stable JSON paths after export. Additional gameplay systems can add Inspector properties in `addons/zombonz/ZombonzMapItem.cs`, scene handles in `MapScene.cs`, relationships in `MapGameplay.cs`, static previews in `GameplayPreview.cs`, and import/export mappings in `MapDocument.cs`. Their data schema and runtime behavior are defined in TypeScript.

For the C# build and headless editor check, put the Godot .NET executable on `PATH` as `godot`, or set `GODOT` to its full path. On Windows, use the `_console.exe` executable so check output is visible:

```text
npm run editor:check
```

The check imports **Bunker and Asylum inside the actual Godot 4.7 .NET editor**, then repeats in the standalone runner. A forced GLB import catches editor-specific mesh conversion failures even with a warm cache. Both contexts check prop materials and foot anchoring, architecture PBR maps, gameplay model sizes, chalk-only initial wall guns, saved perk paints, and preview toggles. They save and reopen scenes, verify untouched maps produce no JSON edits, move linked gameplay objects, rename a barrier, exercise every add-object choice and repeated exports, and export temporary copies through the same TypeScript validator as the dock. Refresh must preserve level edits and recover from a missing asset; preview imports must not extract new files into browser assets. Invalid exports must leave those files unchanged. The committed maps and local authoring scenes are not changed by the smoke test. CI runs the same check with Godot 4.7.2 .NET.

For a visual check, run `res://tests/PreviewCapture.tscn` with the normal renderer (not `--headless`). It renders a prop corner from each map into PNGs in Godot's user data directory, or in an output directory supplied after `--` on the command line. Add `--gameplay` after that output directory to capture gameplay-object galleries. This is an optional verification scene, not the game.
